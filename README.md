# 🚀 OZ AI 6기 - Git & GitHub 학습 정리

## 📌 1. Git 기초와 버전 관리 (Version Control)
프로젝트의 변경 이력을 체계적으로 기록하고 관리하기 위한 필수 명령어들입니다.

* **`git init`**: 현재 작업 중인 폴더를 Git이 관리하는 로컬 저장소로 지정합니다.
* **`git status`**: 현재 파일들의 상태(수정된 파일, 추적되지 않는 파일 등)를 확인합니다.
* **`git add [파일명]`**: 수정한 파일을 커밋 직전의 준비 단계인 Staging Area로 올립니다.
* **`git commit -m "메시지"`**: 스테이징된 파일들을 모아 의미 있는 설명과 함께 하나의 확정된 버전(커밋)으로 저장합니다.

---

## 🌿 2. 브랜치(Branch)와 협업 작업 공간
메인 코드를 안전하게 유지하면서, 새로운 기능을 독립적으로 개발할 수 있는 강력한 기능입니다.

* **브랜치의 개념**: 하나의 프로젝트를 여러 갈래로 나누어 동시에 다양한 작업을 진행할 수 있는 독립된 공간입니다.
* **주요 명령어:**
  * `git branch`: 현재 생성된 브랜치 목록과 내가 위치한 브랜치를 확인합니다.
  * `git switch [브랜치명]`: 다른 브랜치로 이동합니다.
  * `git switch -c [브랜치명]`: 새로운 브랜치를 생성함과 동시에 그곳으로 이동합니다.
  * `git log --all --graph`: 모든 브랜치와 커밋의 흐름을 터미널에 알록달록한 트리(그래프) 구조로 시각화합니다.

---

## 🔀 3. 머지(Merge)의 종류와 원리
나뉘었던 브랜치를 다시 하나로 합치는 병합 과정의 두 가지 핵심 방식입니다.

### ① 패스트 포워드 머지 (Fast-forward Merge)
* **개념**: 메인 브랜치(`main`)에는 새로운 변화(커밋)가 전혀 없고, 오직 작업 브랜치에서만 새로운 커밋들이 쌓였을 때 발생하는 머지 방식입니다.
* **특징**: 깃발(`HEAD`)을 최신 커밋 위치로 '빨리감기' 하듯 슥 밀어주기만 하면 되므로, 별도의 복잡한 충돌 없이 아주 깔끔하고 일직선으로 병합됩니다.

### ② 3-way 머지 (3-Way Merge)
* **개념**: 메인 브랜치와 작업 브랜치 **양쪽 모두** 각자의 길을 가며 새로운 커밋들이 각각 쌓였을 때 사용하는 정석적인 병합 방식입니다.
* **특징**: 양쪽의 공통 조상 커밋을 기준으로 두 갈래의 변화를 비교하여 자동으로 합쳐줍니다. 만약 **동일한 파일의 같은 위치를 양쪽에서 서로 다르게 수정한 경우**에는 충돌(Conflict)이 발생하게 됩니다.

---

## ⚠️ 4. 충돌(Conflict) 해결 방법
* **발생 원리**: 3-way 머지 과정에서 깃이 어떤 코드를 남겨야 할지 판단하지 못할 때 발생합니다.
* **해결 절차**:
  1. 충돌이 난 파일을 직접 열어 불필요한 기호(`<<<<<<<`, `=======`, `>>>>>>>`)를 지우고 원하는 코드로 직접 수정합니다.
  2. `git add [파일명]` 명령어로 수정된 파일을 다시 스테이징합니다.
  3. `git commit -m "메시지"`를 입력하여 최종 병합 커밋을 완료합니다.

---

## 💡 느낀 점 및 배운 점
* 코드를 단순히 작성하는 것을 넘어, 버전별로 안전하게 이력을 관리하고 백업하는 체계를 이해할 수 있었습니다.
* 브랜치를 나누어 독립적으로 개발하는 흐름과, 머지 방식(패스트 포워드 및 3-way)에 따른 병합 원리를 명확히 알게 되었습니다.
* 협업 시 마주칠 수 있는 충돌(Conflict) 상황에서도 당황하지 않고 코드를 분석하여 주도적으로 해결할 수 있는 자신감을 기를 수 있었습니다!
